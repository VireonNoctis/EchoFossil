# EchoFossil

<p align="center">
  <strong>Trace the lineage. Measure the uncertainty. Keep the evidence.</strong><br/>
  A forensic toolkit for studying how synthetic or duplicated material propagates through datasets.
</p>

---

## The problem

Datasets are assembled from many sources, transformed by many pipelines, and reused without complete lineage. As AI-generated material becomes more common, curators may struggle to distinguish original records from generated material, copied content, paraphrases, and records whose origin is unknown.

EchoFossil is planned as a **dataset provenance and contamination investigation toolkit**. It will connect records to source evidence, detect exact and near-duplicate clusters, map likely propagation paths, and document uncertainty.

> **It is not an AI-text detector.** Similarity or writing style is not proof that a record was generated by a model. Reliable lineage and explicit uncertainty take priority over confident guesses.

## Core capabilities

- **Source manifests:** file and record metadata, source identifiers, dataset version, collection time, licence notes, and transformation history when available.
- **Duplicate discovery:** exact hashes first, then configurable near-duplicate candidates.
- **Provenance graph:** link records, files, datasets, transformations, and evidence.
- **Contamination investigation:** surface possible benchmark overlap, recursive synthetic-data reuse, cross-split leakage, and copied material for human review.
- **Confidence with reasons:** separate direct provenance, computed similarity, declared metadata, and unresolved hypotheses.
- **Auditable exports:** machine-readable findings and human-readable summaries without modifying source corpora.

## Investigation workflow

1. Register a read-only dataset snapshot and fingerprint it.
2. Parse metadata and establish stable record identifiers where possible.
3. Calculate exact hashes and optional near-duplicate fingerprints.
4. Connect records to known sources, transformations, and dataset versions.
5. Identify candidate relationships such as duplicate, derived-from, overlaps-with, or unknown.
6. Review ambiguous clusters and record the result.
7. Export a versioned report that can be reproduced against the same snapshots.

## Planned technology stack

| Component | Planned technology | Purpose |
|---|---|---|
| Pipeline and CLI | Python 3.13+ | Ingestion, adapters, investigation workflow |
| Data processing | Polars + DuckDB | Efficient tabular analysis and reproducible queries |
| Columnar interchange | Apache Arrow / Parquet | Typed intermediate data and large-dataset workflows |
| Validation | Pydantic + JSON Schema | Manifests and portable finding contracts |
| Provenance storage | SQLite first; PostgreSQL optional | Local-first research with a route to shared cases |
| Fingerprints | Python prototype; Rust only if profiling justifies it | Correctness first, targeted acceleration later |
| Optional review UI | Svelte + TypeScript | Inspect clusters and provenance paths |
| Tests and CI | pytest, property-based tests, GitHub Actions | Reproducible fixtures and regressions |

This is the intended stack, not a claim that the planned dependencies or features are already implemented.

## What the evidence can establish

| Evidence | Appropriate conclusion |
|---|---|
| Matching cryptographic hashes | The hashed byte sequences match |
| High near-duplicate score | Candidate records merit review; this is not proof of shared authorship |
| Verified source and transformation record | A supported provenance relationship can be recorded |
| A source pipeline's generation label | Evidence whose reliability depends on that pipeline |
| No source record found | Origin is unknown, not necessarily synthetic |
| AI-detector output alone | Insufficient to establish origin |

## Principles

**Evidence before inference.** Conclusions cite the records, metadata, and algorithm that produced them.

**Preserve input.** Analysis runs on immutable or fingerprinted snapshots and does not silently rewrite source corpora.

**Unknown is a valid result.** A relationship may be confirmed, probable, disputed, or unknown.

**Overlap is not automatically contamination.** Quotations, licensed reuse, boilerplate, and common sources require context.

**Design for privacy.** Dataset contents may be personal, copyrighted, confidential, or sensitive. Local-first processing and explicit export are defaults.
